# Support policy

Design DNA is versioned software and guidance, not a promise that every host,
model, framework, browser, or third-party service will behave identically.

## Package support

Package support covers reproducible problems in:

- skill discovery and invocation;
- packaged scripts and schemas;
- installation, update, rollback, and route diagnostics;
- documented Design DNA workflows;
- evaluation and release tooling.

Support for a customer's website implementation, hosting, integrations,
security, legal compliance, content rights, analytics, or ongoing design work is
separate unless a written agreement includes it.

## Before requesting support

Run the package doctor and retain its JSON output. Record:

- Design DNA version;
- Claude Code or Codex version and invocation method;
- operating system and Python/Node versions;
- the exact command or prompt;
- the smallest non-confidential reproduction;
- observed output and expected behavior;
- checks already performed.

Remove credentials, personal data, client-confidential material, and proprietary
assets before sharing evidence.

## Compatibility

The compatibility matrix records only tested combinations. A missing, pending,
blocked, or stale result is not a promise of compatibility. Security fixes may
supersede older versions without preserving every undocumented behavior.

## Commercial support

Response targets, onboarding, customization, update periods, model coverage,
number of licensed users, and service-level commitments must be written into the
purchase agreement. This file does not create an SLA.

No public support address or ticket channel is configured in this source
package. Commercial delivery is blocked until the seller supplies and tests an
owned contact route, names the responsible party, and states its operating
hours and response commitments. Do not substitute a guessed address.

Support evidence is subject to [Data handling and privacy](DATA_HANDLING.md).
