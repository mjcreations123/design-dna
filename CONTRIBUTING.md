# Contributing

Design DNA is proprietary. Contribution access does not grant redistribution or
commercial rights.

Before proposing a change:

1. State the user problem and the exact scope affected.
2. Separate direct evidence from aesthetic inference and authorship speculation.
3. Add the smallest reusable instruction or deterministic tool that solves the
   problem without creating a new house style.
4. Add regression coverage for every executable change.
5. Preserve progressive disclosure: detailed material belongs in a directly
   linked reference, not the runtime entrypoint.
6. Run the complete development audit.
7. Do not update release attestations or manifests until source is frozen.

Changes must not add fabricated business facts, unsafe external actions,
unlicensed assets, secrets, universal aesthetic bans, AI-authorship scores,
deliberate defects, or hidden tracking.

Evidence cards require a review date, confidence, limitations, counterexamples,
and a positive action. Candidate observations must not be promoted to policy
without the evidence required by the registry.
