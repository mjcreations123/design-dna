# Visual-grammar variance

Use this when an accountable owner says multiple sites share the same style,
the same template, or the same producer fingerprint. It applies to the
relationships that organize a rendered site, not to whether its subject matter
could theoretically be replaced with another industry.

## Name the right failure

A website does not fail merely because another legitimate business could use a
similar layout. Useful patterns are transferable, category conventions are
shared, and a design can be broadly applicable without being generic. Do not
ask whether a pharmacy page could become a soda page after changing nouns.

The relevant failure is observed recurrence across actual authorized output:
unrelated sites repeatedly arrive with the same opening, type posture, action
shape, containers, section separators, media placement, route progression, or
mobile collapse without a project, brand, task, content-family, platform, or
maintenance reason. This is a producer house grammar even when the colors,
fonts, photographs, and copy have changed.

Compare only against the smallest owner-authorized recent sibling or lineage
record. If no authorized comparator exists, record that limitation and review
the candidate for project causation; do not invent a hypothetical category-
swap test or claim cross-project difference.

## Map relationship grammar

After deriving the first answer from the current brief and before declaring it
different, describe only the relationships material to this candidate:

- opening or first task-bearing encounter;
- typography posture and hierarchy behavior;
- action and navigation affordance grammar;
- container, backplate, border, and section-separation logic;
- route-body progression and ending;
- media role, placement, crop, and sequence;
- density, alignment, and ordinary-reading behavior;
- mobile transformation rather than desktop stacking;
- shared navigation and footer shell.

These are comparison lenses, not slots that every project must fill or vary.
Use the rendered evidence to identify the smallest recurring cluster. A single
card, underline, filled button, split composition, color field, or familiar
font is never a failure by itself.

## Audit containers rather than banning cards

For every prominent card, panel, bordered box, filled surround, or background
plate, ask:

1. Is the content an independent, repeatable, selectable, actionable, owned,
   or stateful object?
2. Does the enclosure communicate a boundary the visitor needs, such as
   selection, status, comparison, drag scope, warning, or ownership?
3. If the surround disappeared, could spacing, alignment, sequence, a rule, or
   typography express the relationship more directly?
4. Across the whole route, are unrelated content jobs repeatedly being put
   into the same container because the composition otherwise lacks structure?

Cards are appropriate for true units. Panels are appropriate for meaningful
contexts. The defect is automatic cardification or panelification: treating
every paragraph, product, fact, testimonial, step, or CTA as though it needs
its own decorated boundary.

Review background changes in the same way. A field change should communicate
a real context, state, material, atmosphere, chapter, or emphasis transition.
Do not alternate backgrounds merely to announce that a new section began.
Long continuous grounds, deliberate all-over fields, and frequent transitions
all remain available when the rendered sequence earns them.

## Audit action and link affordances

Choose semantics before decoration:

- a button performs an action or changes state;
- a link navigates to a destination;
- an underline supplies link recognition or an intentional editorial
  convention;
- visual prominence follows consequence and task priority.

Do not turn every primary action into the same generic filled rectangle, every
secondary action into the same underlined phrase, or every link into decorative
texture. Conversely, do not remove familiar link underlines where recognition,
accessibility, content density, or the selected visual language needs them.
Audit the complete action set for unexplained monotony and false equivalence,
not for compliance with a shape or underline quota.

## Compare actual output

Freeze the candidate-only first observation before exposing the comparator.
Then compare matching wide and narrow evidence from the current candidate and
the authorized sibling. Ask:

- Which shared foundations are justified?
- Which encounter-level relationships recur?
- Which recurring relationships came from this project's evidence?
- Which appear to be producer defaults?
- Does the narrow version create its own fitting composition or repeat the
  same card-stack collapse used elsewhere?

A failed comparison reopens the earliest unexplained relationship. Do not
close it by rotating color, font, radius, shadow, icon, or motion while keeping
the same opening, progression, containment, and action grammar.

## Preserve freedom

This method creates no novelty score, category-exclusivity requirement,
ingredient blacklist, mandatory layout family, or inverse house style. A
conventional ecommerce grid, split hero, card system, three-column footer,
serif/sans pairing, colored field, rectangular CTA, or underlined link can be
the right answer. The requirement is that the complete relationship cluster is
supported by the current project and does not recur by producer habit.
