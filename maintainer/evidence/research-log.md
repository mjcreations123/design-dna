# Evidence research log

This log records discovery coverage and exclusion decisions. Evidence cards, not search-result snippets, govern the risk registry.

## 2026-08-10 public design-skill landscape and taste-recovery review

### Question and method

After an accountable owner rejected a ten-site demonstration as visually ugly,
the review asked a different question from “which AI-looking ingredients should
be banned?”: which public agent-skill practices help an agent make and reject a
weak visual direction before it produces a technically complete but
unconvincing site?

Public GitHub source was collected from 17 Claude, Codex, and host-neutral skill
collections. A strict front-matter pass found 374 design-relevant `SKILL.md`
paths representing 198 unique bodies after duplicate removal. A broader path
search was retained for discovery only because it also matched unrelated
frontend, asset, and automation skills. High-signal entry, direction, brand,
review, typography, responsive, animation, and design-system bodies were read
closely; the full collection was catalogued but not treated as 198 independent
quality studies. Current web results and Reddit threads were used to locate
recurring practitioner hypotheses, not as empirical prevalence or causation
evidence. Search results from X did not yield reliable primary material and
were not used for a package claim.

### Source matrix

| Source | Useful bounded practice | Excluded or limited practice |
| --- | --- | --- |
| [Anthropic frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) | Ground the purpose, audience, and page job; make the hero a project thesis; use rendered critique. | Its examples of default motifs are calibration language, not a portable ban list. |
| [Claude Design](https://github.com/jiji262/claude-design-skill) | Verify concrete facts, treat real brand/product assets as first-class, declare a visual system, and test in a browser. | Fixed three-direction cycles, named style menus, and its broad prohibitions cannot govern every project. |
| [Designer Skills](https://github.com/julianoczkowski/designer-skills) | Separate brief, system context, screenshot review, and refinement. | Fixed viewport, framework, mobile-first, dark-mode, and numeric recipes are context-specific. |
| [ckw-design](https://github.com/connerkward/ckw-design-skill) | Make a project read, render early, critique the image rather than code alone, and identify the first plausible default. | Its hard spatial metrics and example motif warnings are not a universal aesthetic authority. |
| [Impeccable](https://github.com/pbakaus/impeccable) | Distinguish new work, redesign, critique, polish, boldening, quieting, and hardening; replace a rejected visual world rather than splitting the difference. | Its named command taxonomy and product context files are an implementation, not a universal workflow contract. |
| [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) and other style catalogs | A catalogue can help discover a fitting option or official design system. | A default stack, font bench, palette rotation, layout quota, or style preset becomes a house style and recreates the convergence it claims to prevent. |
| [StyleSeed review](https://github.com/bitjaru/styleseed) and similar score-based reviewers | Coherence, states, and hierarchy are useful review concerns. | Numeric beauty scores and blanket rules for colors, radii, cards, type, and spacing cannot certify taste or cross-genre quality. |
| [Frontend-design skill benchmark](https://github.com/dani-z/frontend-design-skill-benchmark) | A before/after harness can make an output difference visible. | Its pass criteria define success as avoiding named fonts, purple, centered/card layouts, and missing animation; its “with skill” examples repeatedly converge on warm-editorial and terminal treatments. It measures compliance with that doctrine, not broad visual quality or owner taste. |
| Recent Reddit discussions on generic AI sites | Practitioners consistently describe missing positioning, real assets, and actual visual examples as more useful than vague “make it modern” prompts. | Threads are anecdotal, self-selected, and conflict on whether stricter preset systems solve the problem; none was promoted into a style rule. |

### Adopt, adapt, reject

- **Adopt:** source-aware project reads; real material and media decisions;
  reference decomposition rather than copying; visible direction proofs before
  scale; first-impression review; browser-rendered critique; and a clear return
  to direction work when the owner rejects the visual premise.
- **Adapt:** style catalogs and design systems as optional research inputs only
  when the brief, existing product, or authority makes them relevant.
- **Reject:** font, palette, icon, motion, hero, card, eyebrow, section-count,
  score, framework, or device recipes presented as universal anti-AI medicine;
  forced “award” motion; synthetic irregularity; and claims that a detector can
  prove human authorship or beauty.

### Package consequence

Design DNA now adds `taste-calibration.md`, an optional calibration record, a
surface-fidelity review field, explicit direction recovery for “ugly” feedback,
and a boundary that Batch Study fixtures are not portfolio proof. The changes
require project-specific references and a rendered public-encounter judgment
when that judgment is material; they do not prescribe a visual family or create
a new automated taste score.

### Limits

These repositories document workflows and creator preferences, not controlled
outcome research. A high-signal source can show a useful method while still
shipping a rigid taste doctrine. Search availability, repos, and social
discussions change over time. No part of this review proves that a result will
be loved by every audience or impossible to identify as AI-assisted.

### Follow-up registry and community cross-check

The current [Design & UI skills registry](https://www.skills.sh/topic/design),
additional GitHub discovery, Reddit threads, and a current X/Twitter search
were checked after the initial catalog. The registry confirms that the public
ecosystem offers both project-reading/review methods and strongly prescriptive
style operators. Community discussion of scanner-led “unslop” workflows also
contains the useful counterexample: several reviewers described the resulting
before/after work as still generic. This supports using a scanner only to raise
a post-render hypothesis, never as a beauty verdict or an automatic design
generator. X/Twitter again produced announcements and personal reports rather
than stable, method-bearing primary evidence, so it did not create a package
rule.

## 2026-08-02 productive-friction source calibration

The March 2026 preprint *Interrogating Design Homogenization in Web Vibe
Coding* was re-read at its versioned arXiv HTML source. The paper supports
context elicitation, reflective negotiation, and proportionate challenge to a
first plausible default. Its minimalist-whitespace, standard-sans, and
predictable-hero example is explicitly contextual: a global average overriding
a Japanese retail preference. It was not converted into a font, layout, or
style blacklist.

The source was already registered as `EVD-001`, so no duplicate evidence card
was created. That card now has a hash-bound dated summary, medium confidence,
an explicit source-lineage note, and the paper's own limitation: the analysis
does not establish real-world prevalence or validate the proposed mitigation
through controlled outcome research. Its workflow consequence is productive
friction with no universal number of hypotheses, proofs, or rendered options.

## 2026-08-02 YouTube transcript and on-screen-example review

### Question and method

The review asked whether recent practitioner videos support a list of forbidden
AI-looking ingredients or a different kind of quality control. Three long-form
videos were selected because they inspect rendered sites or constructed UI
comparisons on screen rather than discussing aesthetics only in the abstract:

- Y Combinator, *Common Mistakes With Vibe Coded Websites*;
- Y Combinator, *Cursor Head of Design Roasts Startup Websites*; and
- Tom Is Loading, *10 Ways to Prevent AI Slop in Your Frontend UIs*.

Official YouTube descriptions and chapter markers were checked on 2026-08-02.
Timestamped auto-generated transcripts were retrieved and normalized only for
paraphrased claims; repeated words in the machine transcript were not retained
as quotations. Representative frames were then sampled from the actual videos
in a browser. Transcript claims and visual observations were recorded
separately so an unspoken visual detail could not become a claimed reviewer
judgment.

### Registry and package consequence

- `EVD-043`, `EVD-044`, and `EVD-045` retain hash-bound dated summaries with
  timestamp and sampled-frame locators.
- The convergence watch is now a post-render diagnostic. It is prohibited as a
  pre-render style prompt and treats every named font, palette, component,
  motif, effect, and layout as neutral alone.
- The only convergence categories retained are aggregate defaulting,
  irrelevance, inconsistency, and unchecked behavior. Aesthetic findings need
  related rendered observations plus counterevidence; durable truth,
  accessibility, and functional gates remain independently enforceable.
- The Getcrux colored-word treatment is recorded only as a frame observation.
  Because the reviewers did not criticize it, the video supplies no basis for
  a universal split-color or fragment-emphasis ban.
- The reviewed videos name no font family that should be avoided. They support
  testing hierarchy, real copy, consistency, delivery, and fit, not policing
  font names or prescribing a fixed pairing.
- The sources support looking beyond a first default, but not a universal
  number of concepts, models, candidates, cards, proofs, or required creative
  artifacts.

### Limits and exclusions

- Video titles and conversational claims use the language of AI slop and
  vibe-coded work, but the evidence registry does not infer authorship or emit
  an AI score.
- Publisher selection, editing, volunteered examples, reviewer taste, changing
  live sites, and auto-transcript errors all limit generalization.
- Search summaries helped locate timestamps but were not used as a substitute
  for the official descriptions, timestamped transcript, and directly sampled
  video frames.
- No device was promoted into a blacklist. Specific colors, gradients, cards,
  type treatments, hover effects, tabs, labels, and component libraries were
  excluded as standalone detectors because the sources themselves provide
  legitimate and praised counterexamples.

## 2026-07-30 route-family and culturally central publication review

### Question and method

The review asked how a genuinely multi-page range study can preserve
orientation, accessibility, and a recognizable identity without collapsing
every route into one recolored template. It also asked what additional
verification is necessary when Hebrew and culturally central community
language are material to the publication.

Current W3C and MDN guidance was checked for repeated navigation,
cross-document transitions, scroll-progress animation, and Hebrew layout.
First-party and practitioner accounts from Spotify Design, Brad Frost, and NRK
were retained as bounded expert practice for flexible system architecture.
Every source was reduced to a dated maintainer summary; vendor and practitioner
examples were not promoted into universal recipes.

### Comparative source matrix

| Source | Bounded finding | Package consequence | Limitation |
| --- | --- | --- | --- |
| W3C WCAG 2.2 Understanding SC 3.2.3 | Repeated navigation in a set of pages retains the same relative order; secondary and page-specific structure remain possible. | Range studies keep a stable orientation spine while allowing different route bodies. | Informative guidance does not prescribe one visual shell or define which pages belong to one set. |
| MDN View Transition API | Same-origin documents can opt into cross-document transitions with CSS while preserving real navigation. | MPA transitions are optional continuity polish, never evidence of additional routes. | Browser support and behavior remain time-sensitive. |
| MDN scroll-driven animations | Scroll and view progress can drive CSS animation, with feature-query fallbacks. | Scroll stories must retain a complete static state and native scrolling. | Platform capability does not establish usability or justify animation. |
| W3C Hebrew Layout Requirements | Hebrew is RTL and has script-specific punctuation, emphasis, spacing, and optional diacritic considerations. | Mixed Hebrew/English work requires direction, font, wrapping, assistive-technology, and qualified-language review. | The editor's draft is technology-agnostic and cannot validate wording or cultural representation. |
| Spotify Encore | Shared foundations can connect product- and audience-specific local systems. | A route family separates its common spine from route-owned compositions. | One company's organizational model is not a universal architecture. |
| Brad Frost | Shared components, product recipes, and one-off snowflakes occupy different layers. | Range studies classify reuse instead of forcing either one universal template or ten unmanaged copies. | Practitioner vocabulary is optional and does not prove outcome quality. |
| NRK identity guidance | Several coordinated identity channels can vary around a shared conceptual origin. | Route coherence can survive different layouts, media, and motion grammars. | NRK's identity is proprietary and must not be copied. |

### Registry consequence

- `EVD-036` strengthens information-architecture and usability requirements for
  a consistent route-family navigator.
- `EVD-037` and `EVD-038` support progressive enhancement and explicit
  unsupported, reduced-motion, and no-JavaScript verification.
- `EVD-039` adds script-specific typography and responsive checks without
  pretending that a technical standard supplies cultural authority.
- `EVD-041` and `EVD-042` support a constructive shared-foundation and
  local-expression model and an explicit check for one body recipe disguised
  by surface variation. The former Spotify Design source `EVD-040` was
  removed from the active registry on 2026-08-08 after its publisher retired
  the Design site and the exact article redirected to an unrelated product
  homepage; Git history retains the dated card and snapshot.

### Limits and exclusions

- No source proves human authorship or supplies an AI-detection score.
- A distinct route is not established by a new URL, color, font, transition,
  or visual effect alone; route purpose and rendered structure still require
  review.
- Automated route analysis may prove addressability, link integrity, capture
  coverage, and structural similarity. It cannot certify aesthetic quality,
  cultural accuracy, language quality, or community acceptance.
- W3C Hebrew layout guidance supports technical review only. A producer or
  automated checker cannot self-certify culturally central wording or
  representation; a named non-producer authority must accept the exact
  candidate or leave the release gate pending.
- Practitioner systems were used as adopt/adapt/reject references. Their
  tokens, layouts, branded forms, governance structures, and product-specific
  conventions were excluded from the Design DNA house style.

## 2026-07-29 constructive capability review

### Question and method

The review asked which established workflows can strengthen constructive
exploration, content specificity, journey design, and regression evidence
without turning one commercial tool into the Design DNA method. Current
first-party documentation was checked for five bounded capabilities. Claims
were reduced to what the pages actually document, retained as dated summaries,
and mapped only to risks they directly support.

### Comparative capability matrix

| Source | Documented capability | Constructive consequence | Evidence strength | Important limitation |
| --- | --- | --- | --- | --- |
| Figma Make | Accepts existing designs and multiple visual references as context; supports functional previews, iteration, exploration of multiple solutions, and copying preview snapshots into editable design layers. | Ground alternatives in project material and compare rendered proof slices before propagating a direction. | High for the documented platform capability; not an outcome study. | A vendor feature page cannot establish that outputs are materially divergent, appropriate, accessible, lawful, or high quality. |
| Relume Style Guide Builder | Starts concept work after a sitemap and wireframes exist; supports multiple concepts, reusable visual-system controls, and presentation of up to three concepts. | Separate information architecture and wireframing from visual concept selection, then record meaningful differences between concepts. | High for the documented workflow; not comparative design research. | Built-in concepts may still differ mainly by surface settings, and the component workflow is not a universal design process. |
| Storybook | Treats rendered component states as test cases, supports simulated interactions and assertions, and compares story images with accepted visual baselines. | Preserve state coverage and pair behavioral assertions with reviewed visual-regression evidence where maintenance risk warrants it. | High for the documented testing capability. | Component tests and pixel diffs do not prove whole-journey usability, content truth, accessibility, responsive quality, or aesthetic merit. |
| Atlassian Design System | Separates consistent voice from situation-dependent tone and applies that distinction across interfaces, websites, and communications. | Define project-specific voice traits, vary tone by journey moment, and keep terminology coherent without repeating one cadence everywhere. | High as first-party design guidance; brand-specific in application. | Atlassian's personality traits are not a reusable house voice and must not be copied into unrelated brands. |
| U.S. Web Design System | Guides complex forms through transparency, meaningful chunks, progressive disclosure, progress, help, save-and-resume, mobile constraints, and calm recovery. | Treat forms as end-to-end service journeys and validate interruption, help, error, and recovery paths as well as the happy path. | High as official public-service guidance. | The pattern is not a universal recipe; linear progress, flexible order, or saved state can be wrong for some conditional, short, anonymous, or sensitive flows. |

### Registry consequence

- `EVD-031` and `EVD-032` independently support
  `RISK-EXPLORE-001`: open briefs need visible design-space exploration, not
  one unrendered idea followed by cosmetic variants.
- `EVD-031` also supports system grounding, and `EVD-032` supports staged
  information-architecture decisions.
- `EVD-033` supports interaction-state and visual-regression evidence without
  replacing route-level or human review.
- `EVD-034` strengthens the copy-specificity method with an explicit
  voice-versus-tone distinction.
- `EVD-035` strengthens whole-journey and information-architecture review for
  complex forms and services.

### Limits and exclusions

- The Figma, Relume, and Storybook pages are vendor or platform capability
  claims. They establish what the documented workflow can do, not what every
  output does and not whether one tool should be required.
- Atlassian and USWDS are strong official guidance for their stated contexts.
  Their brand traits, content patterns, components, and institutional choices
  are not universal defaults.
- Community discussions and anecdotes helped identify the exploration question
  but were used for discovery only. They were not promoted as prevalence,
  causation, quality, or authorship evidence.
- No aesthetic trait, framework, component library, font, workflow, tool, or
  visual imperfection proves AI or human authorship. The registry authorizes
  reviewable quality risks and constructive responses, never an AI detector.
- Rendered divergence is necessary evidence for an open brief, not sufficient
  proof of quality. Alternatives still require truthful content, relevant
  references, task fit, accessibility, implementation feasibility, and an
  accountable selection decision.

## 2026-07-29 ambition and convergence delta

### Channels and observations

- Current Reddit vibe-coding and web-design discussions plus Hacker News
  threads were reviewed for owner-reported and unbriefed-reviewer signals.
- Repeated observations included template-like spacing and hover behavior,
  generic rounded-card structure, low contrast, oversized display type,
  repeated decorative labels, starter residue, empty or misleading links,
  confusing copy, questionable image details, and weak project personality.
- A useful additional failure pattern was over-propagation: one locally
  appropriate motif, animation, label, card, crop, or surface treatment is
  repeated through every section until the result feels generated by a single
  recipe.
- Multiple participants disputed whether any style, library, or tool can prove
  authorship. The discussions support review candidates and owner-perception
  tests, not an AI detector.

### Package consequence

- No new font, color, component library, visual style, or effect was banned.
- Existing convergence and specificity guidance remains the evidence-backed
  response to fashionable sameness.
- Accountable-owner reports that work is plain, boring, under-designed, or too
  safe exposed a separate contract gap: avoidance rules could produce a
  competent but low-energy safe minimum. `RISK-AMBITION-001` was therefore
  added on owner-policy grounds, with a positive expression method, project
  records, behavioral cases, destructive visual tests, and rendered-review
  criteria.
- At that stage, the method proposed limiting motif propagation and requiring
  pace changes so “more pizzazz” would not become more repeated decoration.
  Design DNA 4.0 supersedes that prescription: current review asks whether
  conspicuous repetition has a project reason and never requires a motif limit,
  pace change, or other aesthetic move in isolation.
- Rendered Coffee and Relay Room counterexamples showed that high saturation,
  giant type, tickers, and offset rectangles can be loud yet still feel flat.
  The ambition contract now distinguishes project depth from surface volume.
- The rebuilt Coffee benchmark exposed two implementation blind spots during
  adversarial review: observer-gated reveal classes left blank full-page
  captures, and a 320-pixel timeline clipped its longest heading while a
  document-level overflow check still reported no overflow. Runtime guidance,
  behavioral review requirements, and the source scanner now require fail-open
  content visibility plus element-level longest-content inspection.

### Limits

- Community posts remain qualitative discovery material. They do not establish
  prevalence, quality, or authorship and were not promoted to a duplicate
  evidence card.
- Aesthetic energy is brief-dependent. Quiet, dense, utilitarian, heritage, or
  restrained work remains valid when the task, evidence, and accountable owner
  support it.

## 2026-08-11 direction-diversity review

### Question

An owner found that recent outputs had stopped looking generic or obviously
machine-made, but still felt like variations of one studio answer. The review
asked whether the portable skill was accidentally producing a safe house
grammar and what process change could reduce that risk without adding a style
blacklist.

### Sources checked

- Doshi and Hauser, *Science Advances* (2024), on individually improved but
  collectively more similar AI-assisted stories.
- Anderson, Shah, and Kreminski, CHI EA (2024), on group-level homogenization
  analysis for ChatGPT-assisted ideation.
- Wadinambiarachchi et al. (2024 preprint), on AI-image ideation, fixation,
  and divergent thinking.
- Leahy et al., DRS (2018), on design heuristics and less-similar concept
  generation.
- Brad Frost's components, recipes, and snowflakes model, plus WCAG 2.2
  consistent navigation guidance.

### Decision

The sources are adjacent-process evidence, not a detector for website quality,
AI use, or originality. They support one narrow intervention: before broad
implementation of an unrelated public build with owner-identified recurrence
risk, derive a brief-native encounter, externalize a materially different
counter-answer, then inspect authorized rendered evidence after an unprimed
first observation. Reuse shared access, navigation, and platform foundations
where justified; do not reuse an unexplained page recipe.

### Limits

- No study above proves a particular website is attractive, unattractive, or
  AI-generated.
- Variation in a font, palette, shape, media crop, or animation alone does
  not establish a different public encounter.
- The resulting Project Contrast record remains qualitative, owner-scoped,
  authorization-bound, and explicitly incapable of issuing an aesthetic score.

## 2026-08-23 reasoning fidelity and qualification reliability review

### Method

This pass tested a different failure mode: whether a polished rationale,
single successful generation, or public regression suite could be mistaken for
reliable design behavior. Primary research and official guidance were reviewed
for reasoning-to-artifact fidelity, first impressions, design convergence,
productive friction, repeated agent trials, contamination, evaluation gaming,
and protected promotion evidence. Each transfer was constrained to the exact
gap it could support; none was treated as a visual style source.

### Resulting runtime and maintainer changes

- Direction grounding now includes a private, provisional perception-and-stakes
  hypothesis: likely mistaken category, visitor stakes or uncertainty, and the
  wrong posture that would betray the brief. It cannot become public labels or
  a fixed visual slot.
- Final review now reconciles every concrete consequential commitment as
  realized, partial, missing, or superseded against an exact artifact or
  behavior. Confident rationale and a successful build are not evidence.
- Unprimed review now records perceived category, stakes, and next action, but
  treats delayed or hybrid recognition as valid when it serves the project.
- Qualification architecture separates development, regression, and protected
  promotion evidence; reports first-pass consistency and the weakest trial;
  and fails closed on empty, stale, mixed-build, or publicly exposed holdout
  evidence.

No reviewed source justified mandatory photos, a font family, a component
shape, a complexity target, a style rotation, a universal page formula, or a
beauty score. Those would replace one convergence basin with another.
