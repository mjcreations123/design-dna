# Current shadcn theme signatures are versioned

## Claim

Framework-default review must follow the current configured preset and token
format rather than assume one permanent shadcn visual signature.

## Observation

Current shadcn documentation exposes preset choices in `components.json`, uses
semantic tokens, documents a default neutral OKLCH scaffold, derives a radius
scale, and offers multiple base colors. Its July 2026 changelog also makes Base
UI the default primitive while retaining Radix support.

## Scope and limitations

The documentation describes a configurable component system, not proof that a
project retained defaults or that any shadcn project is generic.

## Counterexamples

A project may deliberately retain a preset for internal continuity, product
density, accessibility, or maintenance and still be highly specific.

## Positive action

Inspect the actual preset, primitives, base color, tokens, components, and
composition; flag only a sufficiently complete unexamined cluster and never
library presence or isolated OKLCH use.

## Supports

`RISK-FWK-001`

## Validation

Maintain positive and negative scanner fixtures for current default-like and
project-specific configurations, and review the official changelog quarterly.

## Retention

Public platform documentation; preserve a dated excerpt and review within 90
days.
