# Real-browser evidence can complement a bounded review harness

## Claim

Screenshots, viewport changes, interaction checks, and console or network
observations from a real browser materially improve front-end verification when
they are bound to the exact route, state, build, and method.

## Observation

Microsoft's pinned Apache-2.0 Playwright CLI documents browser navigation,
interaction, screenshot, emulation, and diagnostic commands that can support
those checks.

## Scope and limitations

The CLI is one optional path. It should not be globally installed when an
existing browser or project harness is sufficient, and its output does not by
itself establish accessibility, visual quality, truth, or user acceptance.
Logged-in profiles, file access, uploads, and arbitrary evaluation can expose
private data or broaden authority.

## Counterexamples

A static source repair may need only the bundled reviewer; an authenticated
workflow may require a deliberately authorized existing session; a canvas or
hardware-dependent interaction can need different evidence.

## Positive action

Resolve or pin the tool for the task, use an isolated credential-free profile
by default, declare bounded scenarios, and bind saved observations to the same
candidate while preserving limitations.

## Validation

Exercise at least one representative route and state, inspect the saved image,
record console or request failures separately, and prove that the optional path
complements rather than replaces the schema-bound reviewer.
