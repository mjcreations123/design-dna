# Typed implementation should preserve evidence rather than launder it

## Claim

Production-quality typed web code should parse untrusted values at boundaries,
retain precise evidence internally, and reject casts or comments that merely
make an unsupported claim look checked.

## Observation

The pinned MIT-licensed anti-slop repository implements opinionated Oxlint
rules and an installer workflow. Its strongest transferable mechanisms are
boundary parsing, precise inference, avoiding widen-then-assert and chained
assertions, substantive assertion justification, configuration merging,
current version resolution, and refusing to weaken a check to reach green.

## Scope and limitations

The repository is a TypeScript/JavaScript lint plugin, not a visual-design
system. Its identifier-shape ban and Effect-, mocking-, typeof-, or
unknown-parameter preferences are stack or team policy and are not portable
website-quality truths. A bare `SAFETY:` marker also passes its comment regex,
so the marker itself cannot be treated as evidence.

## Counterexamples

A runtime type check, module mock, broad boundary object, or assertion can be
correct when the project architecture and concrete invariant support it. An
unusual symbol name says nothing about rendered quality.

## Positive action

Adopt the evidence-preserving mechanisms conditionally in typed projects.
Merge compatible tooling, name the real invariant behind an assertion, and
report unresolved findings without importing a foreign lint dialect wholesale.

## Supports

## Validation

Test boundary parsing, chained assertions, widen-then-assert laundering, empty
assertion comments, checker configuration merging, and a project whose stack
legitimately chooses different mocking or runtime-check policy.

## Retention

Pinned public MIT-licensed repository evidence. Recheck upstream behavior and
license within 90 days before changing the adapted implementation rules.
