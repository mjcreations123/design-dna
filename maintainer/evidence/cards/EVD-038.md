# Scroll progress can drive an enhancement without owning the content

## Claim

CSS scroll- and view-progress timelines can connect motion to reading progress,
but essential information must remain available when that enhancement is
unsupported or disabled.

## Observation

MDN documents scroll-driven animations using scroll progress and view progress
timelines, together with feature queries for unsupported implementations. The
mechanism changes an animation timeline; it does not require replacing native
scrolling or moving semantic content out of the document.

## Scope and limitations

This is platform documentation, not usability evidence and not permission to
animate every section. Support, performance, compositing, and assistive
technology behavior still need testing in the target environment.

## Counterexamples

A simple article can be better without scroll-linked motion. Progress that
conveys essential state only through animation, hijacks scrolling, or leaves
content invisible outside an animation range is not a valid enhancement.

## Positive action

Bind at most a few purposeful effects to a documented reading or orientation
job, retain native scrolling, make the static state complete, use feature
queries, and provide a deliberately composed reduced-motion path.

## Supports

`RISK-UX-001`

## Validation

Test normal, fast, reverse, interrupted, keyboard, touch, unsupported,
reduced-motion, and JavaScript-disabled paths. Confirm that all text, links,
headings, and controls remain visible and usable without the animation.
