# Cross-document transitions can enhance real multi-page navigation

## Claim

Same-origin multi-page documents can opt into a native visual transition
without replacing ordinary document navigation or requiring JavaScript.

## Observation

MDN documents cross-document View Transitions for MPAs. Both the current and
destination document opt in with `@view-transition { navigation: auto; }`.
Navigation remains cross-document, and the basic enhancement needs no
JavaScript.

## Scope and limitations

Browser support and behavior can change, the feature currently applies to
same-origin documents, and a transition says nothing about whether ten routes
have ten useful ideas. The API must not become a reason to intercept links,
fake pages, or hide content.

## Counterexamples

A conventional site may need no animated page transition. A transition that
delays a critical task, causes disorientation, or fails reduced-motion review
should be removed even when the API is supported.

## Positive action

Start with working links and complete documents. Add a short transition only
where it improves continuity, keep the default navigation path intact, and
verify unsupported, interrupted, back-forward, and reduced-motion behavior.

## Supports

`RISK-UX-001`

## Validation

Enter every route directly, reload it, navigate with JavaScript disabled, test
unsupported browsers and back-forward traversal, and capture a matched
normal-motion and reduced-motion behavior record.
