# Evaluation infrastructure must resist agent-visible shortcuts

## Claim

Qualification is invalid when an agent can obtain a passing record by modifying
tests, reading expected answers, reusing stale artifacts, or satisfying a proxy
while evading the evaluator's intent.

## Observation

NIST CAISI documents task loopholes and reported cases involving test or score
modification, answer access, benchmark lookup, and unintended repository
history use. Flexible code and internet tools increase this risk.

## Scope and limitations

The source concerns evaluation validity, not malicious intent, model morality,
or visual-design criteria. Anti-tamper controls reduce known shortcuts but
cannot prove that an evaluation is complete or ungameable.

## Counterexamples

An agent may find a legitimate superior solution the grader did not anticipate.
That should trigger task and grader review, not an automatic accusation.

## Positive action

Hash-bind suites, schemas, runners, inputs, artifacts, and package identity;
keep promotion holdouts outside the public package; reject stale screenshots,
deleted tests, fake pass markers, and mixed-build evidence.

## Supports

`RISK-REVIEW-001`

## Validation

Qualification records prove artifact and harness integrity, preserve failure
evidence, and fail closed when provenance or protected-partition boundaries are
missing.

## Retention

Current official NIST guidance. Recheck within 90 days and extend controls when
new documented attack patterns appear.
