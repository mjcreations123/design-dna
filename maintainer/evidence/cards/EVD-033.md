# Behavioral and visual checks expose different regressions

## Claim

Rendered component states should carry both interaction expectations and
reviewable visual baselines when regression risk justifies them.

## Observation

Storybook documents stories as component test cases across states, interaction
tests that simulate user behavior and assert results, browser and CI execution,
and visual tests that compare rendered story snapshots with accepted baselines
to reveal unintended interface changes.

## Scope and limitations

Component stories and image diffs do not prove whole-route usability, service
completion, accessibility, responsive quality, content accuracy, or subjective
design merit. Snapshot noise and stale baselines can also hide poor review.

## Counterexamples

A disposable proof of concept may use focused manual evidence instead of a
persistent component harness. Reusable, stateful, or release-critical
interfaces benefit more from repeatable state coverage.

## Positive action

Represent meaningful default, loading, empty, error, success, long-content, and
interactive states. Exercise the user action, assert the outcome, compare
rendered results with an approved baseline, and require a reviewer to explain
every accepted change.

## Supports

`RISK-UX-001`

## Validation

Review the state inventory, interaction assertions, stable baseline
environment, diff approvals, and CI result; supplement it with route-level,
responsive, accessibility, and real-content checks.

## Retention

Public platform documentation; retain a dated summary and review within 90
days because testing capabilities and integrations can change.
