# Vibe-coded applications require an explicit security boundary

## Claim

Interface polish and prompting reduce neither the need for security review nor
the risk of recurrent implementation vulnerabilities in vibe-coded systems.

## Observation

The 2026 study reports recurring patterns including placeholder logic,
unfiltered input, and secret exposure, attributing them to lifecycle limitations
such as memory loss, locally optimized objectives, and incomplete security
knowledge.

## Scope and limitations

The study concerns a collected application corpus and does not establish that
every generated or assisted project is insecure. This skill is not a security
audit.

## Counterexamples

Teams can use mature engineering, threat modeling, specialist review, testing,
and operational controls to produce secure AI-assisted systems.

## Positive action

Block broad production-readiness claims until applicable security, privacy,
data, integration, and operational specialists have reviewed the real system
and environment.
