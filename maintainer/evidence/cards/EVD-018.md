# Components require page-context and user testing

## Claim

Component-level accessibility does not prove that a complete page or task is accessible and usable.

## Observation

USWDS expects teams to test components in their own site context and conduct page-level user testing because a design system cannot predict every use case.

## Scope and limitations

The guidance is written for U.S. government work but the page-context principle generalizes.

## Counterexamples

Small, low-risk changes may need only proportionate validation.

## Positive action

Separate component checks, expert accessibility review, and representative target-user task validation.

## Supports

`RISK-UX-001`

## Validation

Require explicit user-validation status for high-risk and transactional fixtures.

## Retention

Public government design-system guidance.
