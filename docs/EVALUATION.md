# Evaluation guide

## Separate the questions

Evaluate Design DNA in four layers:

1. **Discovery:** Did the intended host actually load the skill?
2. **Behavior:** Did the run follow the skill's material, truth, scope, and
   verification requirements?
3. **Artifact quality:** Did the implemented site perform its real task and
   avoid unexamined generic convergence?
4. **Comparative value:** Did repeated skill runs improve relevant outcomes
   against repeated baseline runs without creating a different house style?

Passing one layer does not prove another.

## Required run identity

Every controlled result must retain:

- host and trusted host-native evidence;
- provider, model, model version, reasoning effort, and safe generation
  configuration;
- exact package and driver hashes;
- task, input snapshot, run number, variant, timing, and exit status;
- exact artifact hashes and reviewer-bound screenshots;
- limitations and unperformed checks.

Secrets, tokens, hidden system prompts, and private account data must not be
stored in evaluation artifacts.

## Representative coverage

The release suite must include all four surface modes, multiple scopes and
stacks, existing and greenfield projects, sparse and dense content, responsive
constraints, localization, adversarial instructions, and implicit discovery.

Lifecycle-sensitive cases should cover subscription/billing, identity and
account recovery, operational location, and messaging/notifications. Public
content cases should exercise editorial, portfolio, local-business, commerce,
and evidence/claim boundaries.

## Rendered review

Bind each review to the exact build, run, route, viewport, browser, preferences,
and artifact hash. Review mobile and desktop at minimum; add intermediate
widths, zoom/text scaling, keyboard, touch, reduced motion, forced colors,
loading, error, empty, offline, and long-content states when applicable.

Rendered automation establishes captured browser behavior. It does not replace
perception, implementation, accessibility, or target-user judgment.

## Interpretation

Do not produce an AI probability or infer authorship from aesthetics. Report
specific observed causes, counterevidence, fixes, verification, and remaining
limits. Explicit disclosures and source behavior are stronger evidence than
trend resemblance.

Release qualification requires the complete contract in
`maintainer/evals/README.md`; diagnostic forward tests must remain labeled as
diagnostic.
