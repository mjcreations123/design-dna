# Design DNA defect audit

This is the consolidated correction ledger for the September 2026 audit.
It includes the Hachnasas Orchim, electronics-store, and HOA postmortems plus
independent failures reproduced while reviewing the skill itself. It is a
development work record; a row is not a release claim. Final test and release
evidence is recorded below when the source tree is frozen.

## Source selection and transfer

1. Research descriptions and gallery URLs could be promoted into visual
   authority without complete generated source evidence.
2. Source quality and organization/brief fit could be self-certified with
   generic pass flags and an unrelated evidence file.
3. Failed, incomplete, inaccessible, and consent-blocked studies could be
   described as usable static references.
4. A source's dominant experience could be represented by an incidental font,
   color, card, control dimension, or small animation. The Niagara Falls
   analogy concerns the memorable whole experience; it is not a literal UI
   label or a ban on typography and color as meaningful source signatures.
5. A copied first screen could coexist with an invented lower-page layout,
   navigation, footer, section transitions, or public-copy hierarchy.
6. A source could be declared dominant on one route while its actual carrier
   appeared only on another.
7. Selected sources could remain in older tables without contributing to the
   component-level transfer map.
8. Observed source states could disappear from the build mapping without
   exact transfer or a verified omission.

## Construction authority and fidelity

9. Source plans could be written or rebound after visible code already existed.
10. Baseline detection missed ordinary JSX tags, generated output directories,
    element factories, imported UI, and additional framework/template extensions.
11. One source marker could be reused on unrelated descendants or extra roots.
12. Component IDs could disagree with the actual rendered component root.
13. Per-component style claims could borrow values from anywhere in a source's
    style file, or use an irrelevant font property to satisfy layout/motion.
14. A valid source frame hash could be attached to an unrelated viewport,
    state, or path.
15. Behavior carriers could cite an existing but unrelated recording event or
    pass merely because some control existed on the named component.
16. Assets could wear a valid ID while serving unrelated bytes; declared media
    kind, crop, temporal behavior, and source-to-output derivation were incomplete.
17. Painted pseudo-elements and embedded browsing surfaces could escape the
    component and media census.
18. First-screen checks could miss hidden, inactive, deferred, imported, or
    encoded future UI.
19. Required owner-pattern, contrast, direction-challenge, and connected-
    experience checks could be bypassed by invoking the main gate directly.
20. A failed first-screen gate did not produce an enforceable, recorded
    prohibition against later broad implementation.
21. Distinct canonical URL strings, including query aliases, could count as
    distinct routes while serving the same body and job.
22. Existing sites could become permanently trapped in a legacy baseline with
    no truthful path for an audited, scoped change.
23. Font declarations could conceal fallback rendering or missing licensing/
    approved deterministic substitution evidence.

## Source-study runtime

24. Timed source dialogs poisoned later interaction attempts, producing a
    generic incomplete-census error without a useful source target.
25. Normal timer scheduling gaps blocked an otherwise observed source before
    its actual modal/control defects could be assessed.
26. Early watcher timestamps, ownership, and navigation lifetime were
    inconsistent; stale registrations could reappear on later documents.
27. One modal generated many duplicate descendant events and screenshots,
    while its exact ambient selector was missing.
28. Source studies had no complete progress, loop, total duration, screenshot,
    attachment-loss, process cancellation, or shared concurrency boundary.
    A later watchdog could mark failure while a hung close still held the
    pending operation open past that deadline.
29. Controller completion accepted fake artifacts, could remain mutable, and
    was not initially bound into actual observer/recorder results.
30. Progress journals could be reused, copied between sources, or validated by
    hashes without validating event sequence, counters, terminal state, and
    terminal artifact identities.
31. Recorder dwell could be requested for effectively unlimited time, and
    wide-profile processing waited while its controller aged during narrow
    capture.
32. Postprocessing could stall without durable progress; synthetic timer
    heartbeats initially concealed a silent child process.
33. Snapshot-write failures, stale cached artifact hashes, missing failure
    files, and secondary exceptions could hide the original cause.
34. Recorder terminal output omitted preserved partial-study artifact bindings,
    and browser cleanup/false completion remained untested until a full run.

## Internal proof workflow

35. The required proof-source record could not be produced by any packaged CLI.
36. Static manifest checks could pass without a rendered specimen or without
    proving that the served output came from the declared source file.
37. Wide and narrow style values were tested against both viewports at once,
    rejecting correct responsive designs.
38. The mandatory internal label contradicted byte-equal source text matching.
39. Positive tests used invented source metadata and non-PNG bytes with a real
    site's URL, masking the missing real capture-to-build path.
40. Proof scans missed fallback fonts, extra framed/embedded UI, hidden
    sections, delayed UI, and source/runtime mismatches. Inherited-opacity
    descendants could also pollute the visible source component map.
41. Repeated proof runs reused screenshot paths, overwriting evidence referenced
    by earlier immutable reports.

## Reporting, installation, and verification

42. Gate output truncated actionable failures and could give research language
    more apparent authority than the actual rendered result.
43. A failed-gate disclosure could coexist with a local link framed as the
    requested finished website.
44. Documentation required unlimited research retries and contradicted the
    separately allowed internal proof path.
45. Manual URL-to-path conversion crashed or silently skipped CLI execution in
    installation paths containing spaces, percent signs, or other encoded text.
46. The parser dependency required a newer Node version than advertised and
    was not reliably discoverable from a direct skill installation.
47. Generated Python caches contaminated the distributable runtime.
48. Intermediate tests against changing source, discarded command-session
    metadata, and unrealistic positive fixtures could be mistaken for final
    verification.
49. A project lock changed the very build fingerprint it was protecting, and
    gate/authorization writers did not all share that lock.
50. Failed final and maintenance runs could bind their prohibition to the
    mutable latest-gate file, invalidating the earlier record on the next run.
51. A hardlink could make an apparently contained evidence file alias bytes
    outside the project.
52. The first-screen validator demanded complete future routes/states before
    construction of those routes was permitted.
53. Literal source-copy text and one universal crop could reject truthful
    project copy and observed responsive media arrangements.
54. Generated assets required approval from a first screen that already needed
    those assets, creating a circular workflow.
55. Custom font aliases could be misclassified as fallback, while a loaded
    alias could also conceal an unrelated actual glyph face.
56. DOM-provided safe-state attributes and ARIA could override dangerous-action
    classification, including open-close and activating-key paths; drag/touch-
    only controls could escape source discovery. Browser-tool listeners needed
    separation from actual source listeners to avoid false gesture gaps.
57. A completed maintenance run could be revalidated as an isolated first
    screen instead of its full scoped-change coverage.
58. Documentation and contract tests retained fixed reference quotas after
    the owner required a project-specific, coverage-justified multi-source set.
    The complete suite also exposed an obsolete two-rejection assertion;
    the regression now requires the actual one-serious-rejected-alternative
    failure and does not weaken the production selection rule.
59. A stored pass flag had no packaged reporting helper requiring complete
    current readiness before presenting a finished-site link.
60. Maintainer commands could use a system Python with user-only dependencies
    that the intentionally isolated test attester cannot load.
61. A standard gate dry-run created an evidence directory despite performing
    no rendered run; internal-proof verdicts also truncated the displayed errors.
62. Maintenance could use a mutable canonical census as its historical
    baseline, which the next gate would overwrite. Asset replacement also
    needed an explicit pre-baseline new-ID workflow retaining old evidence.
63. An image sequence changing its `src` during decode could be mislabeled as
    corrupt media. The tool now distinguishes a changing source state from a
    genuinely broken image and retains the observed frame and exact cause.
64. Browser preflight could accept a launchable Playwright that lacked the
    recorder's timestamped capture API. Private encoder-progress support also
    needed an explicit tested-version boundary.
65. New font/content gate records were absent from the verifier's exact ledger
    contract, so emitted evidence could be rejected during later readiness.
66. Activating construction/maintenance authority changed the source-map hash
    without refreshing its dossier binding, blocking the next gate.
67. Imperative and declarative closed-shadow content could disappear from the
    interaction census, including direct text, pseudo-element material, and
    content in out-of-process frames. Current and actually observed transient
    material now retain typed coverage gaps, including after hiding or host
    removal. Permanently hidden/empty roots, browser-native roots and empty
    clearfix pseudo-elements are distinguished; frame selectors stay scoped.
    Sixteen canonical adverse/positive browser tests passed for these paths.
68. Generic delegated event listeners could be mistaken for required custom
    gestures, blocking ordinary modern sources. Nonmaterial hooks remain
    explicit unverified candidates; observed gesture affordances still require
    real coverage and are never counted as exercised merely because a hook exists.
69. A recorder's representative capture selected the initial blank browser
    frame. It now binds the actual navigated source entry, while preserving the
    complete raw timeline and rejecting substitution of its blank frame.
70. A one-viewport document-height cap rejected a single source-authored tall
    mobile hero or pinned opening sequence. Standard proof scope now uses its
    exact measured source-region authority, retaining second-region, excess-
    height, stale-source and undeclared-component rejection.
71. Real proof tests used the Windows-only Python launcher and a platform-
    specific font assumption. CI also needed explicit FFmpeg provisioning for
    mandatory source-recording tests.
72. The Python dependency lock required 3.11 while advertising 3.10 support;
    all three 3.10 CI jobs failed before tests. The compatible closure is now
    pinned, hash-checked and guarded against repeating that mismatch.
73. Trusted interpreter aliases and internally allocated macOS temporary roots
    were rejected as unsafe links. Artifact, validator and caller-supplied
    project links remain restricted.
74. Link-test cleanup used Windows directory-removal semantics on POSIX
    symlinks. Browser fixtures also inherited CI dependency settings and could
    accidentally load the wrong provider.
75. Windows-native tests were counted as skipped on Linux/macOS, conflicting
    with the zero-skip release contract. A separate, hash-bound applicability
    policy now preserves those tests on every Windows job and records their
    genuine non-applicability elsewhere. Ordinary skips still block CI.
76. The mandatory source-study guide lacked a contents map and failed the
    package audit. Its existing sections now have a concise linked map.
77. Observer startup/early-exit paths could retain an owned study lease after
    the process ended. Failures now propagate through owned-resource cleanup
    before the terminal error is emitted. Startup and observed-source failure
    regressions confirm that the run's leases are released and a sibling's
    live lease is preserved.
78. A full-suite timeout discarded captured stdout/stderr, and descendant-held
    pipes could extend the timeout. Private spooling, retained redacted
    incomplete diagnostics, and bounded owned-process cleanup are now tested.
    The revised bounded allowance drops no tests and still requires a complete
    successful run; a timeout or partial summary can never certify a pass.
79. A test-fixture cache returned an old digest after file bytes changed at
    the same length and their original mtime was restored. Hashing now always
    reads current bytes; the recording-result cache is removed. Only successful
    PNG decoding is cached by exact bytes, stated size and decoder identity.
    Eight focused regressions passed, including restored-mtime mutations,
    malformed PNGs, payload/ledger changes and runtime-dependency changes.

80. Shared browser/parser dependencies had been verified using process-local
    settings only, leaving a fresh empty project unable to resolve them.
    The two previously unset user-level Design DNA paths are now configured
    and tested against the pinned bundle. Installation guidance preserves
    existing settings and distinguishes configuration from host activation.

81. Missing-mechanism and missing-first-screen regressions omitted required
    observation states before their fixtures could reach the real validator.
    Each now builds the valid bound baseline first, removes the particular
    evidence under test, refreshes its outer digest and asserts the intended
    rejection. The complete run exposed the second occurrence rather than
    allowing a fixture crash to stand in for gate coverage.

82. The documented CI promotion changed the same compatibility file that the
    imported tests had verified, invalidating its own evidence. A positive
    fixture concealed this by changing only an in-memory compatibility object.
    CI results are now derived from fully validated canonical imports while
    the on-disk source declaration stays frozen. All input hashes, exact
    artifact/job/platform bindings and skip checks remain required. Missing,
    unsafe, malformed, partial or invalid imports cannot certify a complete
    matrix entry; explicit pass claims retain their citation and timestamp
    obligations. The fixed-state no-import regression now uses an isolated
    fixture instead of assuming the package will never contain real CI imports.

83. A local compatibility pass could be mistaken for portable historical
    evidence, even though its verifier requires the reader's exact interpreter
    and platform. Publishing that source flag broke other readers' audits;
    editing it after the run also invalidated the attested inputs. The release
    procedure now keeps this declaration pending and reports the actual local
    result through its separate exact-host attestation. It does not claim a new
    portable local-proof protocol or substitute that result for remote CI.

84. Python 3.10's default unittest display omitted the method from the
    parenthesized identity, unlike the newer interpreter used locally. The
    skipped-test and native-execution verifiers therefore received ambiguous
    or incomplete identities. The release runner now emits each ordinary
    test's actual public `id()` independently of that display format. Real
    failures, skipped tests and native tracking are unchanged; nonstandard
    class-fixture/subtest descriptions are not turned into invented plain IDs.

85. A completed test process could lose its detailed output when later result
    parsing, applicability, source, schema or publication checks rejected it.
    All three initial Python 3.10 CI jobs returned only a skip-identity error
    and no retained test artifact. Rejected output now has a durable private
    diagnostic by default and an explicit redacted JSON destination for CI.
    It remains non-release evidence with unknown validated test counts;
    unsafe destinations and unverified stream bytes cannot be exported as a
    successful artifact. Existing timeout and process-cleanup checks remain.

86. The first diagnostic-redaction correction could alter fixed record keys,
    source identities and status markers when a credential value was short,
    or repeatedly expand a placeholder that matched a configured secret.
    Redaction now operates on untrusted content, preserves producer-owned
    metadata and uses a collision-free, repeat-stable marker. Actual isolated
    CLI cases cover short values and placeholder collisions as well as normal
    credentials and private paths. Unknown arbitrary encodings are not claimed
    to be perfectly recognizable.

87. The command-line attester could publish an `OK` result containing unwaived
    skipped tests, even though a later release audit would reject it. The CLI
    now verifies the exact waiver policy before publishing a would-be pass;
    the raw-record API still preserves truthful failed-run diagnostics.

88. Checking that an attestation output did not exist before a long run did
    not prevent the final replacement operation from overwriting a file
    created meanwhile. The four immutable attestation CLIs now use atomic
    create-only publication. Competing output survives, a losing writer's
    prepared bytes remain recoverable, and mutable journals/reports retain
    their existing update behavior.

89. macOS fixture allocations inherited `/var` temporary-directory aliases,
    triggering strict project-path rejection and inconsistent containment
    comparisons across many tests. The release test process now canonicalizes
    its own allocator root before creating fixtures. Explicit caller-provided
    project aliases remain rejected; no source/evidence link rule is waived.

90. A redaction regression rejected the username substring anywhere in its
    complete record. On GitHub's `runner` account this falsely matched valid
    `EvalRunnerV3Tests` metadata. The test now verifies the exact sanitized
    disclosure text while retaining legitimate protocol identifiers.

## Verification and remaining boundaries

Verification includes adverse cases and usable positive paths: actual PNG
capture, responsive proof rendering, a full two-profile recorder, actual glyph
font checks, installed-path execution, and strict maintenance callbacks on
explicitly synthetic census fixtures. The maintenance fixture is not a claim
that a full public website passed a browser-tested maintenance gate.

After the final closed-root/runtime changes, the 26 source-runtime, 16
closed-root and 59 browser-hardening cases passed on the canonical files, with
zero skips. These 101 focused checks do not replace the separate complete test
attestation. Earlier attempts exceeded their 3,600- and 7,200-second limits and
established no full-suite pass. The latter retained its incomplete diagnostics
and verified owned-process cleanup; its one fixture error is addressed in row 81.

A complete run ending `2026-09-06T11:27:00Z` executed 1,373 tests with zero
skips, including all four Windows-native cases. It recorded 1,371 passing
tests, one obsolete assertion failure (row 58) and one fixture error (row 81).
That is a completed **failed** run, not final verification. Its exact record
was preserved outside the distributable package before applying corrections;
the corrected source requires a new complete attestation.

After those corrections, both exact dossier regressions passed on the
canonical files, along with 15 canonical CI-import/platform checks. The latter
use explicitly synthetic provider records to test the verifier; they are not
successful remote GitHub runs. These focused results still do not replace the
new complete current-source attestation.

The subsequent exact local run ending `2026-09-06T15:23:00Z` passed all
1,386 tests with zero failures, errors or skips. Its clean development audit
and verified installation parity were committed and pushed as `ade0558`.
The initial remote Python 3.10 jobs then exposed the reporting issues above;
their missing detailed output cannot be reconstructed. Follow-on changes
require fresh current-source verification, not relabeling that earlier pass.

For the owner's local Windows skill test, the complete installed runtime
remains byte-identical to that 1,386-test pass: tree identity
`5fee085c44345cdcf74df52a9fa9d3360069d848a451a2be3621850a3658f79a`.
The subsequent changes are maintainer verification/reporting code and tests,
not website-building code. Across the affected checks, 117 tests passed: the
combined invocation had 115 passing tests and one import-only working-directory
error; that module's two tests then passed from the repository root. These
focused results are not a replacement or relabeling of a complete current
package attestation. Renewed whole-package and cross-platform qualification
remains pending. The local website test must still follow every applicable
source-study, construction, first-screen, final-gate and review requirement.

The authoritative current local results are in `maintainer/attestations/`:
`test-attestation.json`, `install-lifecycle.json`, `route-verification.json`,
and `codex-plugin-validation.json`.
Each record is valid only when its inputs match the exact current tree. Missing
or stale records establish no pass. The [release procedure](RELEASE.md) and
[compatibility matrix](../maintainer/compatibility/matrix.yml) distinguish local
verification, host-native qualification, remote CI and publication.

No local script can prove aesthetic perfection or prevent an agent with
arbitrary write access from ignoring every tool. These checks validate their
explicit evidence contracts and expose violations. Human quality judgments,
owner acceptance, host-native behavior, remote CI, and publication status must
be reported only from the evidence actually obtained.
